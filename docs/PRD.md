# Evalith 产品需求文档（PRD）

状态：整理稿，待确认｜2026-11-05。本文记录已讨论的产品需求；阶段安排见[开发阶段路线](开发阶段路线.md)，具体实现和技术选型仍需验证。

## 用户与核心价值

主要用户是需要评估业务 Agent 的开发者和业务负责人。前者了解项目与运行方式，后者了解业务目标与可接受结果；同一人也可承担两个角色。产品帮助用户从本地项目资料和业务需求出发，形成可追溯的评测资产、完成执行准备并查看证据，降低手工设计和维护评测的成本。

## 产品目标

Evalith 是一个面向不同业务 Agent 的评测工作台。用户提供本地项目、相关资料和业务需求，通过与模型的项目会话，设计并准备项目专属评测资产；用户自主选择题目、预算并执行，逐题查看结果和证据。

它应支持不同类型的 Agent 任务，包括但不限于对话、文件、API、事件和异步工作流；不以单一业务或交互形式为前提。不承诺所有项目零配置接入，也不把模型生成的内容直接视为经过验证的业务真值。

## 主要流程

1. **配置模型服务**：用户添加或选择模型服务，填写所需服务地址、模型及凭据并测试连接。相同服务可按用途复用。
2. **创建项目**：首页以卡片展示项目；用户选择本地项目导入，并可补充 Agent 相关资料、需求文档等。
3. **项目会话**：进入项目后自动开启该项目的主会话。模型先主动分析项目并给出精简的初步理解，用户可以调整理解与评测方向、补充需求；模型有足够把握或用户主动认为可以继续后，才进入题目与规则设计。首版每项目一条持续主会话，题目按题目集组织。
4. **准备评测资产**：会话尽可能同时设计和准备题目、评分规则、测试数据、环境配置及检查逻辑，并创建和检查测试环境。生成的题目自动进入题目集；系统展示来源、准备状态及需要用户补充的问题。实际发起评测由用户操作。
5. **选择并执行**：用户在项目侧边栏浏览题目集、点击查看题目详情，勾选本次题目，查看费用预估并可设置本次预算后发起运行。
6. **查看结果**：每完成一道题立即保存并在侧边栏显示，用户可在其他题目继续执行时查看其结果、过程和证据；历史结果保留。

## 项目与资料

项目保存会话、导入资料、题目集、环境配置和执行记录。用户可补充资料供会话分析，系统展示分析范围及引用来源。资料不足、业务规则存在冲突或模型存在不确定性时，应显式呈现，并允许用户补充和修订。具体文件选择与排除交互待设计。

模型处理资料时应明确所使用的模型服务和资料范围；密钥等敏感配置不应被当作普通项目资料发送给模型。

## 会话与题目集

项目导入后，模型先提供最小的项目理解，包括识别到的 Agent 或相关流程、关键资料来源及影响评测方向的主要未知项，不应把初步推断当成已确认事实。用户可通过对话纠正、补充资料或调整希望评测的范围。模型在讨论中说明仍缺少哪些关键信息；当它判断已有足够依据，或用户明确表示可以继续时，才开始生成题目和规则。用户选择继续不代表未知规则已被确认，生成结果仍须保留不确定性与来源。

会话以讨论方式逐步形成评测任务。每题应能查看任务目标、输入或触发方式、适用条件、评分规则、验证方式、相关来源和准备状态。题目不限定为问答形式；检查可根据任务需要使用状态、文件、轨迹、语义判断或人工复核等方式。

生成题目时，模型根据项目的业务内容自动分类并组织题目集；分类依据来自项目资料和会话中确认的评测方向，不能预设所有项目具有相同业务类别。用户可以查看并调整题目分类，执行时可按分类浏览和勾选题目。

题目准备状态至少区分：已生成但需要补充或检查、已完成运行准备、验证方式已校准。未完成准备的原因应可查看；准备完成不等于业务规则或模型能力已经证明正确。

自动进入题目集不代表题目或检查已经校准。用户可查看、修改和组织题目；资料不足、规则冲突或自动检查尚未准备好的情况应可见。修改题目或评分规则时保留旧版本，后续执行使用所选新版本；历史运行及结果始终关联当时实际使用的题目和规则，不随修改改变。

## 测试环境

会话根据项目和任务生成隔离测试环境方案，包括必要依赖、初始化数据、被测 Agent 接入、证据采集、检查与清理。创建前展示计划启动的服务、拟使用的凭据来源、网络依赖和可能产生的费用，由用户确认一次；确认后会话连续完成环境创建、检查及必要的修复，无须逐步确认。问题无法自行解决时告知用户；若修复需要实质改变已确认的凭据、外部访问或费用范围，应先展示变更。产品应支持不同项目所需的环境，不将某一容器或执行框架作为产品要求。

默认使用独立测试数据及可控的外部服务替身，避免使用真实业务数据或产生真实业务副作用。会修改状态的题目使用独立环境或经过验证的重置机制。运行结束或中止后应清理临时资源，清理失败要可见。项目和环境接入可能需要用户提供配置或凭据。

## 模型、凭据与费用

模型配置按用途区分：会话、评分、结果分析、被测 Agent 所需模型，以及任务需要时的其他模型；用户可选择复用已有服务。项目已有凭据可以作为用户明确选择的凭据来源，能否复用取决于项目的接口和配置方式。密钥不得写入题目、日志或评测结果。

执行前按选择的题目、模型和预计调用等展示费用预估、计算依据与不确定项；不可估算的费用显示未知。用户可以设置单次运行预算。系统在发起后续付费调用前检查可用预算，达到上限后停止启动后续题目并保留已有结果；已发出的调用可能导致实际费用超过预估或上限，应如实显示。已产生的过程和结果应保留，未运行的题目标记原因。预算口径、并发和在途任务的精确控制方式需进一步设计验证。

评测预算与结果分析预算分开：用户在运行题目前设置评测预算；整批结束、选择分析范围时，系统展示分析费用预估，用户可另设分析预算。评测预算用尽不影响查看已保存的结果，也不自动消耗分析预算。分析提前停止时保留已产生的分析内容并标明未完成；已发出的调用及不可估算费用应如实显示。

## 执行与结果

执行前展示选择范围、环境准备状态、模型配置和费用预估。环境或必要验证条件不满足时明确原因，不能将缺少必要证据的题目判为通过。支持查看单题详情和运行进度。

每题完成即持久化并更新侧边栏；结果参考 Harbor 工作台的详细程度，展示题目、状态、评分规则、检查结果、证据、可用轨迹或日志、耗时和已知用量/费用。区分业务失败、环境或执行失败、验证失败或待复核、未运行，并保留超时、预算停止等原因；未知用量或费用不记为零。新运行保留独立记录，不覆盖历史结果。

用户可以配置结果分析模型，在本次评测整批结束后选择结果进行分析。支持全选、仅选错误结果、仅选低分结果或自由勾选；低分判断口径待设计。逐题结果仍在运行期间实时显示，但整组分析等待本次运行结束，包括预算停止或中止等终态；未运行题目及缺失分数应明确显示，不能当作零分或错误结果。分析可读取相关项目代码，并结合所选题目的结果、检查、轨迹和可用证据，归纳表现、共同问题及可能原因，必要时给出可追溯的改进建议；区分证据支持的事实与模型推测，缺少资料时说明限制。分析报告单独保存，引用对应运行、题目和代码依据，不修改原始结果；分析所用模型和已知费用可查看。

## 产品边界与后续研究

- 研究在 Rhesis 开源核心上修改或复用会话、题集、指标、模型配置和结果界面；其现有接入通常面向已运行的服务或 SDK 连接，通用环境创建和项目分析需另行验证。
- 参考 LangChain Eval Engineering Skill 的发现、任务和验证器设计流程，以及 Harbor 的运行结果体验与潜在执行能力；不预先将产品绑定某一种后端。
- 仍需讨论：资料导入细节、题目集的组织与修改方式、环境创建的可视化进度和异常恢复、费用估算与预算口径、结果详情和模型兼容范围。技术选型、部署与源码改造方案尚未确定。

## MVP 验收目标

1. 用户可配置模型、导入本地项目并补充文档，在项目主会话中获得带来源的初步理解；在模型判断依据足够或用户明确继续前不生成题目。
2. 会话能生成按业务内容分类的题目、规则、测试数据、环境配置和检查逻辑；题目自动进入题目集，来源、未确认项和准备状态可见。用户可编辑、调整分类并保留历史版本。
3. 用户确认环境方案后，系统能创建和检查隔离环境，执行准备失败和清理失败有明确状态；不擅自使用真实业务数据或产生真实业务副作用。
4. 用户能查看题目并选择运行范围，看到费用预估和未知项，可设置评测预算；完成一题即保存并展示结果，失败、中止和预算停止后已产生的结果仍可查看。
5. 整批结束后可按全部、错误、低分或自由选择范围配置并发起分析；分析可读取相关代码，保留来源、推测、已知费用和独立预算，报告不覆盖原始结果。
6. 使用至少两个不同交互类型的合成任务验证上述通用流程，例如文件或状态任务与对话任务；它们只用于验证能力，不定义产品业务范围。需验证环境隔离、正确/错误/证据缺失及预算停止，不能用替身运行声称真实模型能力。

## 不在首版承诺范围

任意仓库一键零配置接入、生产系统或真实业务副作用、无人工介入地确认所有业务规则、所有执行后端及任务类型开箱即用、多用户协作和云托管。实际可支持的项目、模型及安全边界应如实展示，不支持的任务不得静默标记通过。
