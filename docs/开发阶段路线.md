# Evalith 开发阶段路线

状态：产品阶段路线，待确认｜2026-11-05

依据：[PRD](PRD.md) 和 [Rhesis 源码适配调研](Rhesis源码适配调研.md)。这里规定阶段交付与验收，不是逐文件实施计划；不代表已确定直接 fork、技术栈、期限或开发完成。

## 阶段 0：确定复用方式和技术边界

**做什么**：固定 Rhesis 源码版本，梳理项目、Architect、题集、模型、运行结果的调用及数据依赖；对比直接修改、抽取模块和服务集成，明确许可证与品牌素材边界。用合成任务验证本地资料访问、非对话输入、可隔离环境和独立检查的最小接入。确定本地目录访问和执行服务的权限边界。

**交付与验收**：形成带证据的复用/新建清单、代码组织和升级策略、环境执行候选与限制；合成任务证明关键接口可行，不能用静态源码推测代替实际验证。遇到不适用的 Rhesis 抽象有明确替代或扩展方案。

**已知起点**：Rhesis 本地浅克隆已存在，基础页面与用户配置模型的连接测试曾可用；运行镜像使用 `latest`，未证明与冻结源码一致。工作台已停止。不得把该体验当作对完整业务功能的验证。

## 阶段 1：项目工作区与会话理解

**依赖**：阶段 0 确定代码组织和安全的本地资料访问方式。

**做什么**：配置模型服务，创建项目卡片、选择本地项目和补充资料；进入项目时建立项目主会话。会话先分析并给出精简理解、来源和未知项，用户可纠正方向；只有模型判断依据足够或用户明确继续时进入题目设计。

**Rhesis 候选**：项目、Architect 消息和结构化计划、模型配置；新增本地项目资料接入和项目工作区整合。

**验收**：重开项目可恢复正确会话；不同项目资料隔离；可定位来源且未知事项可见；敏感凭据不进入普通分析上下文；尚未满足继续条件时不生成题目。模型或资料读取失败有明确提示。

## 阶段 2：题目与评测资产

**依赖**：阶段 1 的项目上下文与会话。

**做什么**：会话生成任务、评分规则、测试数据、环境方案与检查逻辑，题目自动进入按业务内容分类的题目集；用户查看、编辑和调整分类。保存来源、不确定项和准备状态；题目与规则修改后保留历史版本。

**Rhesis 候选**：题集、指标、计划和生成工具；扩展任务模型，使其不局限于单轮/多轮问答，并调整题目生成的确认交互。生成不代表检查已校准。

**验收**：合成的不同交互类型可表达且入库；用户可追踪来源、修改和选择；不可执行或未校准的题目清晰标记；修改不改变历史运行快照。模型未能准备某项资产时展示缺口，不伪造完成。

## 阶段 3：环境与执行闭环

**依赖**：阶段 0 的执行边界和阶段 2 的题目与验证方式。

**做什么**：生成环境方案并展示服务、凭据来源、网络及费用；用户确认一次后连续创建、检查、必要修复、执行准备和清理。用户按分类查看并勾选题目，配置预算并执行。先实现付费调用前的预算检查和保留部分结果；预算无法可靠控制时只允许使用固定响应替身验证，暂不开放付费运行。每题独立保存运行状态、证据和结果，界面逐题更新。

**Rhesis 候选**：预检、任务调度、结果持久化与展示；新增或接入环境生命周期、Agent 适配和独立验证。Harbor 可作为候选执行后端，但只在技术验证后决定。

**验收**：不同交互类型的合成任务能重复初始化、运行、独立验证、清理；正确、错误和缺失证据可区分。环境失败、中止、预算停止及清理失败可见；已完成结果不丢失；独立数据或经验证重置防止任务互相污染。验证器用已知正确、错误、边界和缺证据样本检查。

## 阶段 4：费用与结果分析

**依赖**：阶段 3 能逐题保存结果和用量；预算守卫应在任何付费运行开放前具备，不能作为后补功能绕过。

**做什么**：完善阶段 3 的预算守卫，展示按题量、模型和预计调用计算的费用预估与未知项；评测和分析分别设预算，调用前检查，记录已发出调用的实际费用与超出情况。整批结束后用户选择全部、错误、低分或自选结果，配置分析模型并生成引用代码和证据的报告。

**Rhesis 候选**：用量、结果页面和 Architect 汇总能力；预算账本、可选范围及独立分析预算需验证并补充。

**验收**：预算中止后已完成结果和部分分析保留，未运行不算失败或零分；未知费用不显示为零。分析只在批次终态执行，可按四种范围选择并追溯原结果、代码和模型，报告不改写原始评测。费用不可预先精确控制的部分在运行前明确显示。

## 阶段 5：MVP 整体验收与完善

**依赖**：阶段 1–4 可组合运行。

**做什么**：按 PRD 完整体验项目导入 → 会话 → 题目和环境 → 选题执行 → 逐题结果 → 批次分析；补齐异常恢复、文档、许可证和数据保留说明。

**验收**：PRD 中 MVP 验收目标全部通过；服务重启或中断后历史和已完成结果可恢复，凭据与敏感数据按约定保护。至少两个不同交互类型的合成任务完成闭环；不据此声称任意项目均可接入或评测结果已经证明业务正确。

## 跨阶段约束和未决项

- 每阶段先做可观察的最小闭环；Rhesis 的复用是候选，具体接口、版本及维护成本以验证结果为准。
- 题目和规则是项目独立资产，执行器能力不足、证据缺失或验证出错时必须显式报告。
- 默认不触及生产数据和真实副作用；用户确认环境方案不等于授权使用未列出的凭据、网络或费用。
- 尚需确定本地访问交互、低分阈值、预算货币和多模型计费、运行中取消/恢复策略、存储保留期限，以及模型兼容矩阵。阶段 0 应消除阻碍架构的未知项，其余在对应阶段设计。
