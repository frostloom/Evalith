# 功能复评与修复

评审主范围为 `966eb80..f5fd140` 的 Rhesis 功能实现，并追踪现有 runner、规则编辑和证据路径。依据为 `docs/PRD.md` 与 `docs/superpowers/specs/2026-11-13-rhesis-functional-design.md`。按用户要求本人执行，无委派；不扩展视觉设计、不修改原 ai-gateway、不自动合并 PR。

## Spec：需求与实际行为

### [P1，已修复] 题目评分修改被原 Grader 默认绑定覆盖

自动生成题目有 `default_grader_ids`。原编辑逻辑在修改 Rubric / checks 后仍保留旧绑定，运行继承时继续执行旧 Grader，用户保存的新评分要求没有生效。回归测试已复现。

现在只有标题、分类、输入等修改继续保留默认绑定；修改 Rubric 或 checks 时，新版本解除题目默认绑定，使用新内置规则。内置 judge 编译时明确包含本版本 Rubric。旧版本绑定、共享 Grader 和历史运行不改写；测试集与本次显式覆盖仍优先，编辑界面明确提醒。

### [P1，已修复] 未确认规则可能在生成后丢失，或没有到达评分模型

模型即使返回空 uncertainties，也不应替用户确认项目未知项。原准备操作仅保存模型返回的未知项，而且 grader 的未知项没有进入编译后的 judge criteria。两条路径均用失败测试复现。

现在完整准备与自然语言 Grader 草稿由服务保留项目待确认项，生成 Grader 的待确认项会随实际 criteria 到达评分模型并保存在结果，证据详情可查看。原有 30 项模型限制全部保留，合并项目未知项时不截断任何一项。仍不将模型评分视为人工校准真值。

### [P2，已修复] 评分预检污染题目定义快照

内置检查数组与题目定义共用对象，runner 给检查加入 judge_model 时同步改变了返回的题目定义。修复为复制后编译；测试同时检查题目定义与不可变版本一致、运行元数据仅存在评分计划中。

## Standards：实现边界与健壮性

仓库根范围未发现额外 AGENTS.md、CONTRIBUTING 或 CODING_STANDARDS。按现有 Pydantic 验证、WorkspaceError 与不可变版本约定审查；工具已覆盖的格式问题不重复列为发现。

### [P2，已修复] 非法 Grader check 参数触发服务异常

scope 的 before validator 在检查类型前对 check 调用 `.get()`。提交字符串、列表、整数或布尔值都会产生 AttributeError，而非预期的 422。现在先验证对象类型，再交给 Pydantic 返回格式错误；四类输入均有回归测试。
