# Evalith MVP 初步设计

状态：已过时，不作为当前产品或技术方案｜2026-11-05。用户要求先讨论不依赖具体项目的通用 PRD，见 [PRD 草案](../../PRD.md)。

## 目标与边界

Evalith 是供开发者和业务负责人使用的本地可视化工作台：分析项目资料，整理并审核有依据的评测任务，在隔离环境中运行，展示业务结果与证据。任务可以是对话、文件、API、事件或异步工作流。项目专属的任务、数据和验证逻辑应可保留；不要求所有项目改成聊天形式。

首版以 AI Gateway 客服全场景为覆盖目标：发现并列出场景及缺口，逐步实现适用变体；同时以 Myink 审核任务检验非对话模型。首批端到端样例只是底座验证，不代表客服场景已覆盖。首版不承诺任意仓库零配置接入、生产数据或真实副作用、自动生成规则即业务真值、多用户/云托管、所有后端同时支持，或通过替身运行证明真实模型能力。

## 从现有项目得到的约束

- Gateway 的 `eval/README.md` 描述六类已有用例、脚本化模型、多轮输入和工具/确认等断言；其离线 runner 仍依赖 MySQL/Redis，且已有独立多轮任务评测。README 中的数量和根 README 不一致，必须以扫描具体版本和清单为准。现有结果为回归基线，不能自动当成独立业务真值。
- Myink 的 `evals/cases/audit` 含审核题；项目 README 描述 pass/rewrite/replan、人工复核及异步任务。`docker-compose.test.yml` 提供临时 PostgreSQL、Redis、RabbitMQ，注明不运行真实 worker 或模型；可参考但不能据此假定端到端已隔离。
- Gateway 现有 cases 报告以 Markdown 和失败快照为主，不能假定提供每项检查和完整业务状态证据；导入时标明原有粒度，不得补造结论。Myink 现有审核评测的 `validate/plan` 不运行模型，真实运行依赖 `--live`；固定响应端到端验证需要确认可注入的真实入口或开发测试适配器，不能假设现成可用。
- 本次仅只读检查，未运行或证明任何接入；两个工作区有未提交内容。分析和运行必须记录代码提交与工作树差异指纹；无法冻结或复现时标记不可比较，不覆盖用户文件。

## 用户流程

1. **项目**：选择本地目录，显示 Git 版本、工作树状态及分析范围；用户可以排除目录。只读分析代码、文档、测试和现有评测，不读取密钥文件或将敏感内容发送模型。
2. **发现**：展示带来源路径、版本、位置的项目事实、现有评测和场景矩阵。每个场景标记已有覆盖、缺口、适用性和证据不足，发现范围与未知项可见。项目文档、代码、测试冲突时并列保留。
3. **任务设计与审核**：先导入已有评测并保留原始来源；分析器可提出带依据的候选任务和检查。编辑/接受/暂缓；代码推导为现状基线，需求证据或业务确认支持的才可标业务验收候选。用户确认的是版本化任务和规则，不等于验证器已经可运行。
4. **准备**：项目接入配置描述初始化、健康检查、触发、状态读取和清理。显示依赖、模型模式、网络、资源和风险；检查未通过的任务不能执行。生成配置和验证器为候选，必须经检查与校准。
5. **运行**：选择已审核、可运行的任务集和冻结的配置。MVP 默认单机串行，固定响应模型用于基础设施和回归；真实模型需明确配置和费用限制。支持取消，记录每次尝试及实际使用配置。
6. **结果**：显示计划/运行/各状态数量、每题证据、每项检查及原因、轨迹或产物、版本、耗时与已知用量；未知不写零。可重跑产生新记录，展示版本差异，不把不同条件下的数字直接当作可比结果。

## 资产和状态

| 对象 | 首版必需内容 |
| --- | --- |
| Project | 本地路径、分析范围、代码版本/工作树指纹、来源索引、接入配置版本 |
| Scenario | 业务能力、来源、已有资产、适用变体、覆盖与缺口、待确认问题 |
| Task | ID/不可变版本、目标、来源与可信状态、输入/事件序列、初始状态、约束、证据要求、验证器引用、限制及清理要求 |
| Environment / adapter | 镜像与依赖、启动/健康检查、输入和状态采集接口、外部替身、隔离/重置/清理、能力声明 |
| Verifier | 版本、检查类型、必需证据、硬约束、已知正确/错误/边界与缺证据校准样本 |
| Run / attempt | 任务及配置快照、各版本指纹、模型模式、生命周期、资源/耗时、原始证据与各检查结果 |

任务生命周期采用候选 → 已审核设计 → 可运行 → 已校准；修改任务或规则生成新版本并使相关就绪/校准状态重新验证。一次运行的结果至少区分通过、业务失败、环境/执行失败、验证失败或待复核、未运行；取消和超时保留明确原因。缺少必需证据不判通过，硬约束失败不能被其他分数抵消。

## 架构与首版技术选择

以下是设计建议，不是已选定或验证的实现：本机 Web 界面 + 本地 Python API/worker，SQLite 存元数据，文件存版本化任务及运行证据；前端采用 React/TypeScript。Python 便于接入 Harbor/Inspect，SQLite 降低单机启动成本。通过本地服务访问明确选定的工作区；单用户本机部署，限制监听地址和路径访问。技术选型可随验证调整。

```text
工作台 → 项目发现 / 场景与任务审核 → 任务版本与运行记录
                                  ↓
                       项目适配器 + 执行后端
                                  ↓
                   隔离环境 → 证据采集 → 独立验证
```

Evalith 保存自己的任务与证据模型；后端适配器显式声明支持能力，编译任务到后端时遇到不支持的字段即阻止运行并说明，保留原生结果。Harbor 是首个接入候选，Inspect 是对照；只在同一代表任务的可执行验证后确定首版实际后端，不承诺两者都产品化。独立验证器应读取可信采集的状态或产物，不能信任 Agent 自报成功。Harbor 分离验证器不会自动继承 Agent 文件变化，数据库状态采集和权限要在验证中证明。

分析器参考 LangChain Eval Engineering Skill 的发现、来源、任务设计、环境与验证器校准流程；其当前实现面向 Harbor。首版分析方式可先是受限只读扫描加模型辅助生成候选，来源定位、冲突和用户审核均为一等数据。模型调用需配置可用提供商、传输范围、限额和失败提示；禁止将未审核的候选静默发布为事实。没有模型时至少可导入和浏览现有资产，不假装已完成自动分析。

## 运行隔离和失败处理

默认从冻结快照或明确记录的工作树构建，不挂载用户工作区为可写；每次尝试使用独立测试数据、唯一资源标识及隔离网络，外部支付等副作用用替身。拒绝使用生产数据库、真实会话和无关凭据；明确允许模型调用时仅注入所需凭据。检查挂载、出网、资源上限、健康及数据初始化；证据脱敏，隐藏验证材料与 agent 可见输入分开。Docker 不是完整的不可信代码安全边界。

快照应记录文件清单和内容摘要，默认排除凭据、忽略文件及其他敏感数据；必需的未跟踪或忽略文件需显式纳入且记录来源和处理方式。仅有指纹无法重建源码：未保存可用快照时标记不可复现。导入的项目脚本和验证器视为不可信代码，执行前展示其来源与权限，在隔离环境中运行，禁止直接在宿主机执行；结果文件采用临时文件加原子落盘，异常退出不得产生看似完整的记录。

流程为准备 → 健康检查 → 初始化 → 触发/等待 → 采集 → 验证 → 清理。任一阶段失败保留阶段及错误；清理即使失败也要记录遗留资源并提供重试清理入口。超时、取消、worker 重启不得覆盖原始尝试；启动后发现中断任务应标记中断并按资源标识进行清理，而非自动重复执行。并发与更强隔离留后续验证。

## 验证与交付顺序

1. **发现和映射**：冻结 Gateway 与 Myink 被测版本；导入现有用例并生成来源/场景清单，人工核对确认流程和 Myink 审核路径。Gateway 需建立覆盖矩阵，未盘点或未运行明确显示。
2. **底座试验**：同一 Gateway 状态变化样例和同一 Myink 非对话审核样例，比较 Harbor、Inspect，必要时增加 Compose 基线。先用固定响应或已知输出，记录启动/清理、隔离、证据、接入修改、异步、耗时及不支持项，再选择首版后端。不能从文档推断已可运行。
3. **最小纵向切片**：项目选择 → 现有任务导入/来源 → 审核 → 环境检查 → 执行 → 可追溯结果；两个项目各跑通一个代表样例。再加入模型辅助候选生成与覆盖视图，逐批扩展 Gateway 客服全场景。
4. **验收**：两类项目均可重复初始化、执行、采证和清理；已知正确、错误、边界及缺失证据样本给出预期验证结果；隔离失败、环境失败、任务失败和不可验证可区分；工作台展示版本/来源/检查与未覆盖项。重新运行不会覆盖历史记录。测试真实模型时单独记录配置、费用与波动，替身只证明基础设施。

里程碑分开验收：底座切片完成意味着两个代表样例通过上述检查，且 Gateway 已识别场景的覆盖状态和缺口可见；这不等于 Gateway 客服全覆盖。客服覆盖目标需继续逐类补齐经确认、可运行并经校准的任务，最终由业务负责人结合场景清单确认覆盖范围；未知和不适用项分别说明。

## 待决定与风险

- 框架、具体版本和源码复用方式待样例验证；Harbor 使用 Apache-2.0，复制/分发需履行许可及适用 NOTICE。不要为了通用性提前 fork 或实现多个后端。
- Gateway 两份 README 用例数不同、工作区有改动；具体用例及业务规则需按冻结版本的源码和测试确认。Myink 实际审核入口、运行和证据路径仍需细查。
- 模型服务与预算、场景高风险规则的最终确认策略、证据保存期限及多人协作尚未决定；首版先暴露配置和不确定状态。
