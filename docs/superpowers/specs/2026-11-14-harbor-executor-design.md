# Harbor as a real executor for command tasks

User direction (2026-11-14): implement Harbor, the last known unimplemented capability. Stage-0 evidence (docs/stage0/evidence/harbor-eval.md) verified Harbor 0.25 end to end on this host — oracle agent, hidden separate verifier, artifact collection, reward 1.0 — and named the gaps: the fail path was never executed, and local projects must be baked into the environment image rather than bind-mounted. This iteration closes both in product form.

Harbor becomes a selectable executor for command-kind tasks. Preparing a Harbor environment verifies the configured harbor CLI (`--version`) and a reachable Docker daemon, copies the project source read-only into the environment directory, and records both versions in the runtime snapshot. Preflight accepts only command tasks for Harbor environments.

At execution, Evalith materializes one Harbor task per case: `task.toml` (schema 1.4, `network_mode = "no-network"`, agent timeout from the executor config, artifacts covering the case work dir and captured output), an `environment/Dockerfile` that bakes the copied project source into the image, and a `solution/solve.sh` that writes the task's input files, runs the configured command with the task's stdin in the project working directory, and records stdout and the exit code as artifacts. The built-in `oracle` agent executes that script — here the "reference solution" is the target under test, which is stated plainly. The verifier is a minimal passing check because scoring stays Evalith's single source of truth: collected artifacts become the observation (`evidence_directory`, `stdout`, `exit_code`, plus recorded Harbor metadata), and the existing check evaluation and judge machinery run unchanged. A nonzero harbor CLI exit is a visible execution failure, never a scored result.

Honest boundaries, stated in the plan and UI: for this backend the container is the isolation boundary — the target runs inside Harbor's no-network container while the harbor CLI itself runs as an owned but unsandboxed host process (it needs the Docker socket and may pull base images), with process-group ownership, timeout, cancellation and output caps preserved. First runs spend minutes building images; per-task images and Harbor's prebuilt sidecar remain in the local Docker cache. Harbor's own reward field is plumbing metadata, not the score of record.

Real validation on this host must cover a passing and a failing deterministic check through a complete run (closing the stage-0 negative-path caveat), using a synthetic project and no credentials, no model calls. Conversation and adaptive tasks remain on the Go bridge; this change does not claim cloud sandboxes, compose service tasks or LLM agents inside Harbor.
