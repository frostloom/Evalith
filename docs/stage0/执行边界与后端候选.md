# 阶段 0：本地访问、执行隔离与后端候选

状态：源码梳理 + 合成任务实跑 + Harbor 0.25.0 实跑｜2026-11-05

## 1. 结论

1. **Rhesis 本身不提供“本地项目目录访问”和“每次运行独立环境”**。它的项目是逻辑租户分区，不是文件系统路径；backend/worker 只挂载 `rhesis-storage`，没有宿主机项目目录；执行是长驻 Celery worker 调用用户已连接的 endpoint，不是创建/重置/清理容器。
2. **本次用合成任务证明了 Evalith 需要的执行边界可以实现**：只读资料挂载 + 路径白名单/符号链接逃逸拒绝/密钥排除、`network none`、只读根文件系统、cap drop、非 root、独立隐藏验证器、通过/失败/未验证三态、清理校验全部实际跑通。
3. **Harbor 0.25.0（Apache-2.0）是可信的首个执行后端候选**：合成文件状态任务真实运行成功，独立 verifier 容器 3/3 通过，容器/网络清理正确。但本地项目目录没有一等挂载方式，异步/长驻服务未演练，失败路径未实跑，冷启动约 3m38s。
4. **不预绑定后端**：阶段 3 应先抽象 Evalith 的执行契约（能力声明 + 环境生命周期 + 证据/验证器 + 清理），再让 Compose 薄执行器、Harbor 或后续后端实现它；Rhesis 的 endpoint 执行只覆盖“已连接服务”的对话/单轮任务。

## 2. 本地项目资料访问边界

### 2.1 Rhesis 现状（源码证据）

- backend/worker 只挂载命名卷 `rhesis-storage:/app/storage`，没有宿主机目录挂载（`docker-compose.yml:149-150`、`:197-198`）。
- 项目模型没有“本地路径”字段；`Project` 是组织/项目租户分区（`models/project.py:16`；`models/mixins.py:231`）。
- 唯一接近“读仓库”的能力是 GitHub URL 下载到进程 CWD 下的临时目录，然后遍历/删除（`services/github.py:183-238`），没有按用户选择的本地目录、排除规则、版本指纹或权限模型。
- Architect 的附件读取只针对消息里的内存文档（`sdk/agents/architect/agent.py:581`；`services/architect/attachments.py:60`），不能读磁盘。
- 因此，**阶段 1 不能假设 Rhesis 能直接读宿主机任意目录**；需要 Evalith 自己的项目访问层。

### 2.2 合成验证（已通过）

合成项目 `stage0/harness/fixtures/project/` 包含：

- `README.md`、`docs/RELEASE_POLICY.md`、`src/release_gate.py`、`data/sample_state.json`：应被读取；
- `.env`、`secrets/credentials.txt`：含合成假密钥，必须排除；
- 运行时创建的 `leak-outside` 符号链接，指向项目根之外：必须拒绝；
- 只读挂载：写探针必须失败。

实际运行结果（`stage0/evidence/runs/20261105T070245Z-summary.json`）：

| 检查 | 结果 |
| --- | --- |
| README/政策/源码/示例数据被收录 | 通过 |
| `.env` 被排除（`excluded_name`） | 通过 |
| `secrets/` 目录被排除 | 通过 |
| 符号链接逃逸被拒绝（`symlink_escape`） | 通过 |
| 项目挂载只读（写探针失败） | 通过 |
| 清单中无合成密钥标记 | 通过 |

### 2.3 建议的权限模型

- 用户显式选择一个或多个本地目录；Evalith 记录绝对路径、选择时间、排除规则和快照指纹，不把路径写入题目或模型上下文。
- 访问层以**只读**方式打开目录，基于 `realpath` 做根目录约束，拒绝符号链接逃逸、设备文件、FIFO、socket；默认排除 `.git`、`.env*`、`secrets/`、`node_modules/`、`.venv/`、常见私钥/凭据文件。
- 读取结果形成带 SHA-256 的快照清单；模型只看到被选中的文本/片段和来源，不看到密钥。二进制/大文件按大小和类型上限跳过并显式记录。
- 分析进程本身放在受限容器中；不把宿主机 Docker socket、用户主目录或生产数据库凭据暴露给容器。
- 每次项目/运行使用独立的租户/项目 scope（Rhesis 的 RLS 已具备）；跨项目资料不得共享缓存。
- 资料不足、被排除、无法读取、版本不一致都要作为可见状态返回，不能静默当作“没有资料”。

## 3. 执行隔离边界

### 3.1 Rhesis 现状（源码证据）

- 执行单元是长驻 Celery worker 中的 asyncio 任务；隔离只有 semaphore/超时，没有新进程/容器/网络命名空间（`jobs/execution/batch/runner.py:292`；`batch/context.py:28-29`）。
- 目标是用户已连接的 endpoint；Rhesis 只负责构建 `{"input": ..., "test_parameters": ..., "files": ...}` 并调用它（`jobs/execution/executors/output_providers.py:105-145`；`batch/invocation.py:272`）。
- 没有环境 create/reset/cleanup；没有每次运行的独立数据；测试之间共享同一个 endpoint 和同一份外部状态。
- 没有内建“隐藏状态验证器”；判定来自指标（LLM/代码评分），指标可以独立但默认不读取被测系统最终状态。
- 预检存在但只在 UI 调用，不自动门禁执行（`services/test_set.py:722`；`routers/preflight.py:248`）。

### 3.2 合成验证（已通过）

`stage0/harness/runner/run.py` 对每个用例：

1. 创建唯一的 state/out 命名卷；
2. 启动 agent 容器：`--network none`、`--read-only`、`--cap-drop ALL`、`--security-opt no-new-privileges`、`--user 65534:65534`、`--memory 128m`、`--pids-limit 64`、`--cpus 0.5`、`/tmp` tmpfs；agent 镜像**不包含** `verify.py`；
3. agent 只读挂载**过滤后的项目快照**（无 `.env`、无 `secrets/`）和只含 `event.json` 的输入目录；验证器用另一个镜像、另一个输入目录（只含 `expectation.json`）；
4. 运行完成后，用**独立容器**和独立代码读取最终状态并给出 verdict；agent 主动探测 `/app/verify.py`、`/input/expectation.json`、`/project/.env`、`/project/secrets/credentials.txt`，runner 另查镜像和挂载内容；
5. 删除容器和卷，检查**本次运行**的容器/卷是否真的消失；Docker 检查错误和删除失败都记录为可见失败。

实际观察到的容器配置（`docker inspect` 证据，来自运行 summary）：

运行结果（通过 / 失败 / 未验证，另加 claim-mismatch 对照）：

| 用例 | 期望 | 外部验证器实际 | 说明 |
| --- | --- | --- | --- |
| 合规释放（release_manager） | 通过 | 通过 | 状态 released，1 条审计，未影响其他 artifact |
| 贡献者批准导致错误释放 | 失败 | 失败 | Rhesis 式“代理自称成功”不足以判定；验证器读取最终状态发现错误 |
| 缺少审计证据 | 未验证 | 未验证 | 状态看起来正确，但缺少必需证据，不判通过 |
| agent 自报错误判定 | 通过 | 通过 | 状态和审计正确，但 agent 自报 `rejected`；claim 只作诊断，不改变 verdict |
| 修改无关 artifact 的 approval | 失败 | 失败 | 只改 doc-18 的 approvals、status 仍为 draft；完整快照比较发现变化 |

清理：每个用例都检查本次运行的容器/卷是否仍然存在；只有 `leftover_containers`、`leftover_volumes`、`command_failures` 和 `inspection_errors` 均为空时 `clean = true`。失败会写入 evidence 并使整体 `all_ok` 为 false。

### 3.3 建议的权限模型

- 默认 `network none`；需要外部服务时使用显式、最小、可审计的出网策略（allowlist/代理），并在运行前展示。
- 每次运行独立命名空间/卷/网络；被测 Agent 不可写项目快照、不可读隐藏验证材料；只暴露任务需要的输入/状态接口。
- 只允许声明的凭据来源注入；密钥不写入题目、日志、结果；日志/证据脱敏。
- 资源上限（CPU/内存/PID/磁盘/超时）显式设置；超时、取消、崩溃、清理失败分别记录；清理失败提供重试入口。
- 容器不是对任意不可信代码的完整安全边界；高风险项目需更强隔离（microVM/远程沙箱）或人工审核。
- 证据采集与验证器分离：验证器读取可信采集的状态/产物，不信任被测 Agent 自报；缺证据不判通过。

### 3.4 凭据、网络与数据边界

- **Rhesis 模型凭据**：模型 `key` 使用 `EncryptedString` 加密存储，读接口不回传；连接测试只返回成功/失败和有限信息（`models/model.py:34`；`routers/model.py:80-131`）。
- **本次运行**：模型 key 使用合成值 `stage0-fake-key`，目标服务无凭据；没有真实 API key 进入题目、日志或结果。模型请求只发往本地 `stage0-stub` 容器。
- **建议边界**：凭据按用途注入到需要它的服务（模型调用、被测服务、数据库），不注入被测 Agent 的普通上下文；题目、测试数据、日志和结果中不得出现密钥；注入失败要显式报错，不能静默降级。
- **网络**：默认不允许出网；需要外部服务时使用显式 allowlist/代理，并在运行前展示；本次 agent 容器 `network none`，无法访问外网或宿主网络。
- **数据**：只用合成数据和确定性替身；不读取生产数据库、真实用户会话或真实业务副作用；运行产物保存在独立目录/卷，按保留策略清理。
- **宿主机**：不向容器暴露 Docker socket、用户主目录或无关凭据；本地项目只读挂载，验证材料不进入被测容器。

## 4. 执行后端候选对比

| 维度 | Rhesis 0.20.1（现状） | Harbor 0.25.0（实跑） | Compose 薄执行器（基线，未实跑） |
| --- | --- | --- | --- |
| 许可 | MIT 核心；EE 另许；官方镜像含 EE | Apache-2.0（需保留 NOTICE） | 自建，依赖各自许可 |
| 任务形态 | 单轮/多轮对话 + endpoint | 任务 = 环境 + 指令 + 隐藏 verifier；文件/状态/服务均可 | 任意，需自建契约 |
| 环境生命周期 | 无；长驻 worker + endpoint | 有；per-task 容器/Compose；`network_mode` 策略 | 需自建，但最灵活 |
| 独立验证器 | 指标评分，非状态验证 | 强：`separate` verifier 容器，只物化声明的 artifacts | 可自建 |
| 本地项目目录 | 无；只能附件/GitHub 读取 | 无直接 bind mount；需烘进镜像或自定义 provider | 可直接挂载（需自己做权限） |
| 异步/长驻服务 | endpoint 模式可调用常驻服务 | Compose + `verifier.collect` 设计上支持，未演练 | 可支持，需自建 |
| 逐题结果/实时 | 已有 TestRun/TestResult + WS | job/trial 结果 + artifacts；无工作台 UI | 需自建 |
| 预算/模型控制 | 资源配额/用量；无货币预算 | 有 token/cost 统计与 timeout（LLM agent） | 需自建 |
| 清理 | 不适用 | 已验证容器/网络清理；镜像缓存保留 | 需自建并验证 |
| 冷启动 | 已有镜像/栈 | 3m38s（首次构建/拉取） | 取决于实现 |
| 失败路径 | 有 Error/Inconclusive 语义 | verifier 设计上可失败；本次未跑负例 | 需自建 |
| 适配结论 | 工作台/数据模型底座，非通用执行器 | 首个执行后端候选，需补本地项目和异步验证 | 作为最小基线/对照 |

详细 Harbor 证据见 [harbor-eval.md](evidence/harbor-eval.md)。

## 5. 支持范围与限制（阶段 0 结论）

| 能力 | 现状 | 阶段 0 判定 |
| --- | --- | --- |
| 对话/单轮任务（已连接 HTTP endpoint） | Rhesis 主链路 | 可复用；本次用合成端点验证接口 |
| 多轮对话 | Rhesis Penelope 执行器 | 源码可复用；本次未用真实模型验证 |
| 文件/状态/事件/API 序列任务 | 无一等模型；只能塞进 `test_parameters` 或自定义 endpoint | 需 Evalith 适配层；本次合成任务证明边界可实现 |
| 本地项目资料读取 | Rhesis 无 | 需新建；本次只读扫描原型通过 |
| 每次运行隔离环境 | Rhesis 无 | 需新建；Compose/Harbor 候选；本次最小隔离通过 |
| 隐藏验证器/状态证据 | Rhesis 指标不是状态验证 | 需新建；本次独立验证器通过 |
| 失败/缺证据判定 | Rhesis 有 Error/Inconclusive，但依赖指标 | 需映射到 Evalith 结果语义；本次三态通过 |
| 预算/费用守卫 | 无货币预算 | 阶段 3–4 必须补齐；不能后补绕过 |
| 真实模型能力 | 本次全部使用确定性替身 | **未验证**；不得把替身运行解释为模型能力 |

## 6. 待解决的具体风险

1. 本地目录访问的产品交互（选择/排除/快照/更新）和权限提示尚未设计；本次只验证了读取原语。
2. 容器挂载在 Docker Desktop/macOS 与 Linux 上的 UID/权限、SELinux、rootless 差异未验证。
3. Harbor 的异步/长驻服务、数据库状态采集、失败路径未实跑；本地项目目录需要自定义 provider 或镜像烘焙。
4. Rhesis 的 endpoint 执行没有环境重置；同一 endpoint 上的状态会跨题目/跨运行累积。若阶段 3 复用 Rhesis 执行器，必须外接环境/重置，或只允许无状态任务。
5. 预算/费用：Rhesis 只有资源配额和 token 计数，没有价格/预算/在途控制；真实模型调用前必须有守卫。
6. 许可与品牌：官方 Dockerfile 会打入 EE 源码，官方镜像含 EE；必须自建 EE-free 镜像并完成品牌替换（见许可审计）。
