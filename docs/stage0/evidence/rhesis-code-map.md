**Project isolation clarification.** The RLS policy (`alembic/.../c3d4e5f6a7b2...py:87-95`) is `project_id = NULLIF(current_setting('app.current_project', true), '')::uuid OR project_id IS NULL OR current_setting('app.current_project', true) = ''`. When the GUC is empty, the last disjunct is true for **every row** covered by this policy, so RLS alone is **not** fail-closed for absent scope. The actual hiding for normal ORM queries comes from the `auto_filter` listener in `models/scope_events.py:231-245`: with an org scope and no project it applies `organization_id = ... AND project_id IS NULL`; with a project it applies `project_id = ... OR project_id IS NULL`. Raw SQL/bulk writes bypass the ORM listener (`scope_events.py:59-66`), so RLS remains a backstop only for org filters, not for no-project filtering. A token-bound/explicit unauthorized project is rejected by `assert_project_access` (`dependencies.py:183-188`); a stale browser header degrades to no scope. Evalith must add an explicit project-membership/allowlist check and must not rely on RLS alone; cross-project and absent-scope denial remain unverified (the stage-0 run created one project).

### 2.2 Architect data dependency summary

`ArchitectSession 1—N ArchitectMessage`; both carry `project_id` (session via `ProjectMixin`, message as a bare column, `models/architect.py:62`). There is no `ArchitectPlan` table: the plan is `session.plan_data` JSONB, and the UI's markdown is re-derived from it each turn. Agent-executed tools read/write **platform rows** via the FastAPI ASGI app under the user's delegation token, not via SQL models directly (`runner.py:256`, `local_tools.py:43`). Therefore the architect's only persistence seams are: (a) `architect_message` / `architect_session`, (b) arbitrary platform entities it creates through HTTP tools, (c) attachments JSONB. There is no per-turn execution history, no plan version, and no state separate from `agent_state`.

## 10. Data dependency graph (text)

Tenant/scope root:

```
Organization
└── Project (RLS partition; request scope = X-Project-Id or token project)
    ├── ProjectMembership ── User
    ├── Endpoint (connection_type, request/response mappings, auth, version_info)
    │   └── TestConfiguration (endpoint_id, test_set_id, attributes{execution_mode,
    │        metrics, evaluation_model_id, execution_model_id, reference_test_run_id})
    │        └── TestRun (status, attributes{task_id, run_config, metric_plan,
    │             version_info, parameters_ref, batch_*})
    │             ├── TestResult (execution, verdict, test_output JSONB, test_metrics JSONB)
    │             │     ├── File* (polymorphic entity_type="TestResult")
    │             │     ├── Annotation / Comment / Tag
    │             │     └── Trace (telemetry, linked by test_run_id/test_result_id)
    │             └── Experiment (optional; versions[] JSONB of parameter values)
    ├── TestSet ──M2M── Test ──M2M── TestSet
    │   │                ├── Prompt (content, expected_response)
    │   │                ├── Requirement ──M2M── Metric
    │   │                ├── Category / Topic / Status / Source
    │   │                └── TestConfiguration JSONB (multi-turn: goal/instructions/
    │   │                     restrictions/scenario/min_turns/max_turns/expected_tool_calls)
    │   └──M2M── Metric (overrides requirement metrics)
    ├── Metric (scope, judge model_id, backend, class_name, config)
    ├── Model (provider_type, model_type, encrypted key)
    ├── Source → Chunk → Embedding
    ├── File* (polymorphic; storage_path, extracted_text, content_hash)
    └── ArchitectSession (mode, plan_data JSONB, agent_state JSONB)
        └── ArchitectMessage (role, content, attachments JSONB, metadata JSONB)
```

Selection/priority chains that matter for Evalith:

1. **Execution payload**: `Test` → (`prompt.content`, `expected_response`) **or** `test.test_configuration` → `EndpointService.invoke_endpoint` → `Endpoint.request_mapping` (with `{{ input }}` / `{{ messages }}` / `{{ files }}`). `TestConfiguration.attributes` supplies execution mode, metric overrides, model overrides, and reference run.
2. **Metrics**: execution-time list in `test_configuration.attributes.metrics` → `test_set.metrics` → `test.requirement.metrics`; then filtered by `metric_scope` and by whether the test carries the metric's `REQUIRED_EXPECTATIONS` (`jobs/execution/evaluation.py:76-124`, `metrics/applicability.py:64-80`). Multi-turn adds a built-in Goal Achievement row (`jobs/execution/metric_plan.py:184-190`).
3. **Models**: per test run only the needed purposes are built — `evaluation` if any non-SDK metric or any multi-turn; `execution` only for live multi-turn (`services/run_models.py:76-90`), both from the run's metric plan plus live re-check (`:194-213`). Per-metric judge models override the evaluation model for that metric (`batch/context.py:109-138`).
4. **Eventing**: domain event → `events.emit` → sinks: DB activity log, `job:{job_id}` WS, `test_run:{id}` coalesced tick. Architect events bypass this bus and publish directly to Redis `ws:events` on `architect:{session_id}` (`event_handler.py:62-75`).
5. **Attachments**: two disjoint paths — platform `File` rows + `StorageService` (+`FilesMixin`), versus architect `architect_message.attachments` JSONB with extracted text only. They do not share storage or lifecycle.

## 11. Stage-0 reuse verdicts (summary)

- **Reuse with an explicit project-membership/allowlist guard**: project tenancy + ORM/RLS filtering (RLS alone permits every project row when the GUC is empty; the ORM auto-filter supplies `project_id IS NULL`, and raw SQL bypasses it); endpoint invocation/invokers; test set → test configuration → test run → test result pipeline; batch execution + cancellation; metric plan/scope filtering; usage/quota counters; run snapshots (`run_config`, `version_info`, `metric_plan`); WS/Redis fan-out; job/activity event bus; model connection tests; preflight checks.
- **Modify**: add a task-kind discriminator beyond `TestType` (or a new sibling model) at the enum/schema/loader/factory points in §6; extend `ArchitectPlan` + `tool_registry.py` + MCP tool YAML for file/state/API/event actions; extend the executor registry; give attachments a storage-backed path if they must survive/scale; make preflight enforceable from the execute path.
- **New**: project-directory/workspace abstraction and storage/mount policy; environment/sandbox lifecycle (create/reset/cleanup) and per-task isolation; state fixtures/setup-teardown model; event/API-sequence assertions and result shape; durable cross-worker conversation/session store; per-run cost budget (money, not counts); prompt/test/metric definition versioning and architect plan/state history.
