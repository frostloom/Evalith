## 1. 结论摘要

1. **Rhesis 值得作为工作台底座，但不适合作为“通用评测执行器”原样使用。** 它的项目租户、题集、模型配置、单轮/多轮执行、逐题结果、运行快照和实时事件可以复用；但本地项目目录、非对话任务、每次运行隔离环境、隐藏状态验证器和货币预算都不在其现有抽象中。
2. **建议“fork MIT 核心 + Evalith 自有执行适配层”，而不是重写、抽取少量模块或把 Rhesis 当作完全独立服务。** 这能保留最重的 UI/数据模型，同时把执行契约留在 Evalith 自己的边界内，避免把对话假设扩散到上游执行器。
3. **合成任务已实际证明边界可实现**：只读项目资料 + 秘密/符号链接排除、非对话事件输入、`network none`/只读根文件系统/非 root 容器、独立隐藏验证器（agent 镜像不含验证器，期望答案只挂载给验证器）、通过/失败/未验证三态、claim-mismatch 对照、清理校验全部通过。
4. **Rhesis 运行时验证已完成到接口层**：模型连接测试、项目/端点/题集/题目/指标创建、单轮执行、逐题结果落库、Architect 会话/Celery/工具路径均已跑通；模型与目标为确定性替身，不代表真实模型能力。运行时使用官方 0.20.1 镜像并用冻结提交的 2 个差异文件替换，完整源码构建的最终层复制未完成（见 §7）。
5. **Harbor 0.25.0 是可信的首个执行后端候选**：合成文件状态任务真实运行成功，独立 verifier 3/3 通过，清理正确；但本地项目挂载、异步/长驻服务和失败路径仍未验证。
6. **许可没有阻塞**，但必须删除 `/ee/`、品牌素材和法律文本，默认关闭 Rhesis 遥测/SaaS 连接，并自建 EE-free 镜像；官方镜像不能重标分发。

### 2.1 固定版本

| 项 | 值 |

| 固定提交 | `ce24bb1993fc545bb0ccb0d8b3951683ac14fff1` |

| 对比执行器 | Harbor `0.25.0`（`harbor-framework/harbor`，Apache-2.0） |

**为什么强调源码一致性**：本地已有的 `ghcr.io/rhesis-ai/backend:latest` 镜像自报 `0.20.1`，但与固定提交比较，`app/services/invokers/common/connection_errors.py` 和 `rest_invoker.py` 两个文件不同（镜像是固定提交的父提交）。因此“镜像版本号相同”不等于“源码一致”。本次完整源码构建在最终 runtime 层复制时超时，记录运行改用官方镜像并把这两个文件只读挂载为冻结版本；迁移到最终 Evalith 构建时仍应使用完整 EE-free 源码构建。

### 2.2 方法

1. 源码静态梳理：项目、Architect、题集、模型、执行、结果、权限、环境、预算、版本快照；每条结论带 `path:line`。
2. 许可/第三方/品牌逐文件审计。
3. 合成任务实跑：不依赖任何真实业务项目，使用确定性替身和本地容器。
4. Rhesis 运行时验证：尝试从固定源码构建（backend/worker venv 完成，最终 runtime 层复制超时）；记录运行使用官方 0.20.1 镜像 + 冻结提交的 2 个差异文件只读挂载。使用 OpenAI 兼容的确定性替身充当“模型”，用合成 HTTP 目标充当“被测 Agent”，走公开 API 创建和执行。
5. Harbor 对照：安装、任务格式、真实运行、清理和能力缺口。

**明确不做**：不使用真实业务数据、真实凭据或真实副作用；不把替身运行解释为真实模型能力；不把静态阅读当成接口验证。

## 3. Rhesis 架构与数据依赖（摘要）

完整表见[源码与数据依赖图](evidence/rhesis-code-map.md)，这里只保留影响复用决策的结构。

### 3.1 对象与关系

```text
Organization
└── Project（RLS 分区；请求用 X-Project-Id 或 token 绑定）
    ├── Endpoint（连接类型、请求/响应映射、认证、version_info）
    │   └── TestConfiguration（endpoint_id、test_set_id、attributes）
    │        └── TestRun（status、attributes{run_config, metric_plan, version_info, task_id}）
    │             └── TestResult（execution、verdict、test_output JSONB、test_metrics JSONB）
    ├── TestSet ──M2M── Test（prompt 或 test_configuration；test_parameters）
    │   └──M2M── Metric（scope、judge model、backend/class）
    ├── Model（provider、加密 key、endpoint）
    └── ArchitectSession（mode、plan_data JSONB、agent_state JSONB）
        └── ArchitectMessage（role、content、attachments JSONB）
```

关键点：

- **项目是逻辑租户，不是本地目录**：`Project` 没有路径/工作区字段；`ProjectMixin` 只是 `project_id` 分区。
- **题目只有两种形态**：单轮 prompt 或带 `goal` 的多轮配置；`test_configuration` 是自由 JSONB，非对话任务没有一等表示。
- **执行是“调用已连接 endpoint”**：worker 组装 `input`/`test_parameters`/`files`，通过 REST/WebSocket/SDK invoker 调用；没有环境创建、重置、清理。
- **结果是指标判定**：`execution`/`verdict` 双轴设计良好，但 verdict 来自指标；没有默认的“读取最终状态”的独立验证器。
- **Architect 是 WebSocket + Celery**：REST 只建会话/读消息；消息经 WS handler 入队，`architect_chat_task` 在 worker 里运行；计划是 `session.plan_data` JSONB，没有版本表。
- **附件与项目文件是两条路**：平台 `File` + 对象存储 vs Architect 的 base64/JSONB 附件；都不等于本地项目目录访问。
- **预算只有资源配额/用量计数**，没有货币预算、价格、预留或在途控制。

## 4. 复用方式比较与建议

| 方式 | 初始成本 | 长期成本 | 主要问题 |
| --- | --- | --- | --- |
| 直接大范围修改 Rhesis | 中 | 高 | 对话假设散布在执行器/类型/schema/指标/前端约 20 处；上游升级冲突大 |
| 只抽取模块 | 高 | 低–中 | 要重建工作台/项目/题集/结果 UI 和认证；模块并非独立发布 |
| 完全服务集成 | 中 | 中 | Rhesis 没有本地项目/环境/验证器/预算；仍需 Evalith UI 和同步；官方镜像含 EE |
| **Fork MIT 核心 + 适配层（建议）** | 中 | 中 | 需要补丁纪律和定期 rebase；但保留最值钱的 UI/数据模型，并把新能力放在自有边界 |

**建议的代码组织**：

```text
evalith/
  workbench/        # fork 的 Rhesis MIT 核心（EE-free、去品牌）
  contracts/        # 任务、环境、后端能力、证据、验证器、预算的稳定契约
  project-access/   # 本地目录选择、快照、排除、来源
  execution/        # 适配层：编译任务到 Compose/Harbor/其他后端
  api/              # Evalith 自有 API/编排（可嵌入 workbench 或独立服务）
  patches/          # 对上游文件的最小补丁，单独记录
```

**边界原则**：

- Rhesis 继续负责“工作台 + 项目/题集/运行/结果”的通用部分；
- Evalith 负责“项目资料访问 + 通用任务/环境 + 独立验证 + 预算”；
- 两者通过稳定的 `TestRun`/`TestResult` 契约和 Evalith 自己的执行契约连接；
- 不把 Harbor/Compose/任何后端写进产品数据模型；后端通过能力声明适配。

**升级策略**：保留 `upstream` 远程，固定基线，功能放在 `evalith/` 新包；对上游文件的修改逐个小 commit 记录；每个上游 minor 版本评估一次；补丁冲突超过阈值时重新评估抽取/服务化。详见[复用与改造清单 §5](复用与改造清单.md)。

## 5. 许可与品牌边界

结论（完整证据见[许可审计](evidence/license-audit.md)）：

- 核心是 MIT Expat，可 fork/修改/分发；`/ee/` 是独立商业许可，**禁止复制/分发**，必须删除而不是禁用。
- 上游 Dockerfile 会把 `ee/` 打进镜像；官方 `ghcr.io/rhesis-ai/*` 镜像含 EE，不能重标分发。
- `BRAND_*` 只能替换 favicon/产品名/两种颜色/字体；wordmark、内联 platypus SVG、约 150 处文案/链接、法律 imprint、ToS/隐私链接仍需代码修改。
- `docker-compose.yml` 默认开启遥测（`OTEL_RHESIS_TELEMETRY_ENABLED:-true`、`telemetry.rhesis.ai`）和平台密钥/SaaS 连接（`ENABLE_RHESIS_KEY:-true`、`api.rhesis.ai`）；Evalith 部署必须显式关闭。
- OWASP 材料是 CC BY-SA 4.0；Redis `7-alpine` 标签可能落到非 BSD 许可版本；字体缺 OFL 文本；镜像未复制 LICENSE/NOTICE。这些是阶段 1 的合规清单项。

## 6. 合成任务与实际执行边界

### 6.1 合成任务

位置：`stage0/harness/`。任务不依赖任何真实业务项目：

- 一个玩具“发布门禁”项目：`docs/RELEASE_POLICY.md` 规定只有 `release_manager` 能发布；
- 一个非对话事件：`{artifact_id, action, actor, mode}`；
- 一个故意有缺陷的 agent：只看 actor 是否在批准列表里，忽略角色，因此贡献者批准也会错误发布；
- 一个独立 verifier：读取最终状态和审计记录，按政策判定，不信任 agent 自报；
- 三态：通过 / 失败 / 未验证（缺审计证据）；另有 claim-mismatch 用例证明 agent 自报不参与状态 verdict，以及 unrelated-mutation 用例证明完整快照比较能发现无关状态变化。
- 每个用例的 `case_ok` 还要求 agent 自身 exit 0、Docker 验证器缺失探针返回预期 exit 0、`docker inspect` 的隔离限制成立、agent 网络/项目写探针符合预期；缺证据、探针错误或 agent 非零退出都不能算通过。

### 6.3 失败与未验证（必须保留）

- 失败用例是**预期失败**：证明“agent 自报成功”不能替代独立状态检查。
- 未验证：Linux 上的 UID/SELinux/rootless 差异、套接字/设备文件/大文件/二进制、并发运行、清理失败重试、更强隔离（microVM/远程沙箱）。
- 未验证：真实项目（尤其需要数据库/多服务/异步工作流）的环境创建与重置。

| 真实模型/Architect 完整工具链 | 未验证 | 仅替身完成会话接口；没有真实模型生成题目/调用工具 |

| 取消/预算/清理 | 未验证 | 源码确认，未运行 |
| 环境创建/重置/隐藏状态验证 | **未验证（Rhesis 不支持）** | 目标状态由宿主机在用例间重置，属于外部补丁 |

**关键失败证据**：Rhesis 的 stub NumericJudge 对下列两种情况都返回 `pass`：

- 贡献者批准就释放（违反合成政策）；
- 释放成功但没有审计记录（缺证据）。

独立 verifier 分别判定 `failed` 和 `unverified`。这就是“指标不是独立状态检查”的直接运行证据；不能据此说 Rhesis 能正确判定业务结果。

Rhesis 流程使用**共享 verifier 的状态契约**，不传 `--require-hidden-access`（Rhesis 流程没有 agent 容器可探测），并为无关 artifact 提供初始完整快照；`pass` 因此返回 `passed`，不再被隔离检查误判为 `unverified`。隔离检查的 `--require-hidden-access` 只由 harness runner 启用。

### 7.3 运行时限制

- Rhesis 执行不创建/重置环境；target 状态在用例间由宿主机重置，这是外部补丁，不是 Rhesis 能力。
- 运行时用的是官方 0.20.1 镜像，不是完整源码构建；2 个差异文件已用冻结提交版本替换。该镜像含 `ee/`，仅本地使用、不得分发。
- 本次为 API 级验证；前端/WebSocket 实时刷新未启动。
- 替身只验证接口与结果链路，不验证真实模型的生成/判定质量。

## 8. 环境执行候选与限制

详见[执行边界与后端候选](执行边界与后端候选.md) 与 [Harbor 评估](evidence/harbor-eval.md)。

### 8.1 Harbor 0.25.0（实跑）

- 官方 `harbor-framework/harbor`，Apache-2.0；Python ≥3.12；Docker 后端。
- 合成文件状态任务真实运行：exit 0、reward 1.0、独立 verifier 3/3、artifact 收集正确、容器/网络清理正确。
- 缺口：没有宿主机项目目录 bind mount（需烘进镜像或自定义 provider）；异步/长驻服务/数据库状态采集未演练；负例（nop）未跑；冷启动 3m38s；镜像缓存会保留。

### 8.2 Rhesis endpoint 执行

- 适合“已有可调用服务”的对话/单轮任务；不适合需要环境生命周期、隐藏状态验证和重置的任务。
- 状态会跨题目/运行累积；没有清理；预算只有资源配额。
- 可作为阶段 1 的工作台底座，不应作为阶段 3 的唯一执行器。

### 8.3 Compose 薄执行器

- 作为最小基线保留：直接控制服务/卷/网络/清理，适合验证 Evalith 契约；代价是调度、超时、错误分类、并发要自建。
- 本次合成 harness 本质上就是它的最小原型，证明边界可行。

**建议**：阶段 3 先定义 Evalith 执行契约（能力声明、准备/检查/初始化/触发/采集/验证/清理、取消、失败分类、证据），再实现 Compose 基线和 Harbor 适配器；不预先绑定某一个后端。

## 10. 对阶段 1 的具体建议

1. **先做 EE-free 构建**：删除 `ee/`、前端 EE 依赖、`ee_bootstrap`；用 `uv sync`（无 ee extra）启动；跑后端健康、项目/模型/题集/运行关键路由；记录镜像 digest 和依赖锁。
2. **建立 Evalith 项目访问层**：只读目录选择、排除规则、快照哈希、来源索引、密钥排除；先不做“任意目录自动分析”，只做用户明确选择的范围。
3. **项目工作区**：在 Rhesis 项目页上增加“资料 / 会话 / 题集 / 结果”结构；自动创建主会话；保留来源和未知项。
4. **Architect 最小改造**：注入项目访问工具；让题目保存自动/可撤销，环境创建单独确认；服务端校验确认状态，不只改文案。
5. **任务契约先于执行器**：在阶段 2/3 之前定下 `Task`、`EnvironmentSpec`、`VerifierSpec`、`Evidence`、`BackendCapabilities` 的稳定字段，避免被 Harbor/Compose 细节绑死。
6. **预算守卫前移**：在任何真实付费调用开放前实现调用前检查、未知费用、部分结果保留；不能用“先跑后补预算”。
7. **保留 Rhesis 上游测试**：把上游测试和 Evalith 契约测试都纳入 CI；升级前先跑。
8. **合规清单**：EE、品牌、遥测、法律文本、NOTICE、字体、Redis 版本、镜像内 LICENSE/NOTICE。
