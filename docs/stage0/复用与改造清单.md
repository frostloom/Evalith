## 结论先行

**建议采用“MIT 核心 fork + Evalith 自有执行适配层”的混合方式，而不是整体重写 Rhesis、抽取少量模块，或把 Rhesis 当作完全独立的外部服务。**

- 直接复用 Rhesis 的项目/租户、题集、模型配置、运行、逐题结果、实时事件、取消和用量基础，可以省掉工作台最重的界面和数据模型。
- 不把通用文件/状态/API/事件任务硬塞进 Rhesis 现有的 Single-Turn/Multi-Turn 执行器；在 Evalith 自有适配层里定义任务、环境、验证器和预算契约，再把结果写回 Rhesis 的 `TestRun`/`TestResult` 展示链路。
- 只在上游做窄缝修改（任务类型判别、项目工作区、Architect 工具与确认交互、执行入口钩子），其余以新文件/新包的方式放在 Evalith 命名空间，降低升级冲突。
- 必须删除 `/ee/`、品牌素材和默认遥测/SaaS 连接，且不能直接分发官方镜像（详见许可审计）。

## 4. 三种复用方式的成本对比

| 方式 | 初始成本 | 长期升级成本 | 主要风险 | 适用判断 |
| --- | --- | --- | --- | --- |
| 直接修改 Rhesis（大范围 fork） | 中 | 高：执行器、测试类型、指标 scope、schema 都是上游活跃区，升级冲突大 | 把对话假设扩散到更多上游文件；测试和迁移成本高 | 不推荐全量改造 |
| 抽取模块（只复用 SDK/invoker/metrics） | 高：需要重建工作台、项目/题集/结果 UI、认证、任务调度 | 低–中：模块边界较干净 | Rhesis 的模块并非独立发布，抽取时仍会拖出 app 模型和依赖；丢掉最值钱的 UI | 不推荐作为首版 |
| 完全服务集成（Rhesis 作为外部服务） | 中：两套部署/认证/数据同步 | 中：按 API 升级，但受 API 缺口限制 | Rhesis 没有本地项目/环境/验证器/预算抽象；仍需 Evalith 自有 UI 和适配层；官方镜像含 EE | 可作为备选，不作为首版 |
| **Fork MIT 核心 + Evalith 适配层（推荐）** | 中：清理 EE/品牌 + 少量窄缝 + 新适配层 | 中：补丁队列 + 定期 rebase；适配层独立演进 | 需要纪律性的上游同步和补丁边界 | 首版最省总成本，且符合 PRD 的“不绑定单一后端” |

## 5. 上游更新策略

1. **固定基线**：以 `ce24bb1` / `0.20.1` 为第一个可复现基线；记录 `VERSION`、commit、构建镜像 digest、依赖锁文件。
2. **双远程**：保留 `upstream`（rhesis-ai/rhesis）和 Evalith 的 `origin`；`upstream/main` 只读，Evalith 功能在 `evalith/main`。
3. **补丁分层**：
   - `evalith/` 新包/新文件：优先级最高，尽量不改上游文件。
   - 窄缝修改：每个修改一个小 commit，commit message 带 `upstream-patch:` 前缀；记录对应上游文件/行。
   - 品牌/EE/遥测清理：单独一组脚本化 patch，便于每次升级重放。
4. **升级节奏**：至少每个上游 minor 版本评估一次；先跑上游后端/SDK 测试和 Evalith 契约测试，再合并；补丁冲突超过阈值（例如 >15 个上游文件或 >500 行）时，重新评估“服务集成/抽取”方案。
5. **不追随 `latest` 镜像**：只用自建 EE-free 镜像并 pin digest；官方 `ghcr` 镜像含 EE，不得重标分发。
6. **许可与品牌回归**：每次升级跑许可/品牌检查清单（EE 目录、logo、遥测默认、法律 imprint、第三方 NOTICE、字体 OFL、Redis 版本）。

## 6. 运行验证证据（摘要）

- **模型连接**：`litellm_proxy` 指向确定性替身，`POST /models/test-connection` 返回成功；这只证明接口可用，不代表真实模型能力。
- **题集/题目/指标/运行**：通过公开 API 创建了合成项目、题集、单轮题目、NumericJudge 指标，并对合成目标执行；结果写入 `TestResult`。
- **合成任务**：独立容器中的非对话事件任务，验证了本地资料读取、`network none`、只读根文件系统、隐藏验证器、通过/失败/未验证三态和清理（见[执行边界与后端候选](执行边界与后端候选.md)）。
- **未验证**：真实模型下的 Architect 完整工具链、前端逐题实时刷新、运行中取消、预算守卫、真实 Harbor 失败路径。详见主报告“已通过/失败/未验证”。

**运行环境限制**：运行时使用官方 0.20.1 镜像（digest 见 `stage0/evidence/rhesis-runtime/README.md`），不是完整源码构建；与冻结提交不同的 2 个 Python 文件以只读 bind mount 替换。backend/worker 的源码构建已完成到 venv，最终 runtime 层复制在 Docker Desktop 上超时。镜像含 `ee/`，仅本地验证、不得分发；frontend 未启动。
