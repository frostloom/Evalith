# 阶段 1：本地项目资料访问边界

状态：实现与合成验证｜2026-11-06

本文说明 Evalith 阶段 1 如何把“用户选择的本地项目”变成只读、可追溯、可核对的分析上下文。实现位于 `evalith/src/evalith/project_access.py`，测试位于 `evalith/tests/test_project_access.py`。

## 1. 运行位置与容器边界

阶段 1 的默认运行方式是**宿主机进程**（`EVALITH_ACCESS_MODE=host`）：用户选择一个绝对路径，Evalith 以当前用户权限只读打开文件。遍历不是“先验证路径字符串、再按路径读取”：导入和每次重扫都用 `O_NOFOLLOW|O_DIRECTORY` 打开项目根目录描述符，并记录根目录的 `(device, inode)`；之后所有子项都以父目录描述符为锚点、用 `O_NOFOLLOW` 逐级打开。这样根目录在验证后被替换为符号链接或另一个目录时，重扫会失败，而不是读取替换后的内容。

阶段 1 **只实现宿主机模式**。容器路径映射、只读挂载、UID/SELinux 语义尚未实现；把 `EVALITH_ACCESS_MODE` 设为非 `host` 会直接拒绝（`container_mode_unavailable`），不会退化为读取容器内任意路径。这是刻意的 fail-closed：在没有验证过的挂载与 UID 模型前，不把“声明了映射”当成安全边界。

范围、凭据和符号链接规则与运行位置无关，容器接入实现后可复用。阶段 1 的验证只覆盖宿主机模式，不能据此宣称容器隔离已完成。

## 2. 选择与范围

用户可以：

- 留空“只分析这些路径”，表示分析整个项目根目录；
- 填写一个或多个相对路径（文件或目录），只分析这些子树；
- 追加排除模式（`fnmatch`，匹配文件名、相对路径或任一路径段）。

无论选择方式如何：

- 绝对路径、空路径、`..` 段一律拒绝（`path_outside_root`）；
- 项目根目录本身不能是符号链接，也不能命中固定敏感名称规则（`secrets`、`credentials` 等）；每次重扫都核对根目录的 `(device, inode)`，身份变化时拒绝并提示重新导入；
- 选定路径及其每个祖先必须不命中排除模式；显式选择被排除的目录/文件会记录为排除且不打开；
- 选定路径必须存在，且只能通过根目录描述符逐级打开；
- 默认排除版本库、依赖、构建产物和缓存（`.git`、`node_modules`、`.venv`、`.next`、`dist`、`build` 等）；
- 单个快照最多 400 个文件、单文件指纹上限 8 MB；超出上限会记录原因，不会静默丢弃。

## 3. 凭据与越界符号链接

固定的敏感名称规则**始终生效，不能被用户选择覆盖**：

- `.git/`、`.ssh/`、`.aws/`、`.gnupg/`、`secrets*`、`.docker/`；
- `.env`、`.env.*`、`*.env`；
- `*.pem`、`*.key`、`*.p12`、`*.pfx`、`*.kdbx`；
- `id_rsa*`、`id_ed25519*`、`id_ecdsa*`；
- `credentials*`、`.npmrc`、`.pypirc`、`.netrc`。

如果用户显式选择 `.env` 或 `secrets/`，请求返回 422（`sensitive_path_denied`），不会读取后再过滤。

符号链接：

- `os.walk(followlinks=False)` 不进入链接目录；
- 链接文件记录为“symbolic link is never followed”后跳过；
- 如果选定的路径本身经过符号链接，拒绝（`symlink_rejected`）；
- 每个选定路径都从已验证的根目录描述符开始逐段 `openat`，不经过路径字符串拼接，因此不存在“校验后被替换”的 TOCTOU 窗口；
- 显式选择与遍历都用 `O_NONBLOCK|O_NOFOLLOW` 打开文件，先 `fstat` 再读取；FIFO/设备/套接字会被拒绝，不会因没有写端而阻塞。

因此不存在“通过链接读到项目外文件”的路径。阶段 0 的合成测试已经验证过同类边界；阶段 1 的单元测试再次覆盖链接文件与链接目录。

## 4. 只读保证

访问层只提供读取：

- 用 `os.open(path, O_RDONLY | O_NOFOLLOW)` 打开；
- 没有任何写入、重命名、删除、创建接口；
- 测试在导入前后比较项目树的文件集合、大小、修改时间与 SHA-256，结果完全一致；
- 不执行项目中的代码，不安装依赖，不解析 shell 命令。

“只读”不是靠容器挂载实现的；即使没有容器，访问层也不会写用户项目。

## 5. 来源与内容指纹

每个被分析的文件记录：

- 项目内相对路径；
- 完整内容的 SHA-256；
- 字节数；
- 修改时间（纳秒）；
- 是否二进制、是否进入模型上下文、未进入的原因；
- 内容脱敏次数。

快照的 `digest` 是对排序后的 `路径\0SHA-256\0` 再取 SHA-256，因此同一组文件内容会得到相同摘要。会话消息同时保存 `sent_scope`：本次实际发送的文件、哈希、字节数、补充资料标题和脱敏数。用户可以在界面右侧核对“资料范围”和“本次发送”，理解中的已知项也带文件路径来源。模型返回的 `known` 项必须带非空来源；服务会对照当前快照来源（以及此前理解的来源）核对，无法核对时拒绝为已知并显示模型错误，而不是把无来源断言渲染成已知事实。

## 6. 敏感内容脱敏

路径规则之外，读入模型上下文的文本还会经过一次内容脱敏：

- `api_key=...`、`token: ...`、`password=...`、`authorization: ...` 形式的赋值；
- 带常见前缀的凭据名，例如 `OPENAI_API_KEY=...`、`DB_PASSWORD=...`、`STRIPE_SECRET=...`、`AWS_ACCESS_KEY_ID=...`、`AWS_SECRET_ACCESS_KEY=...`；
- JSON/带引号的 `"api_key": "..."`、`"client_secret": "..."` 等键值；
- `Bearer ...`；
- 带凭据的连接字符串，例如 `postgresql://alice:password@db/app`、`redis://:password@cache:6379`；
- PEM 私钥块。

文件内容先对**完整解码文本**脱敏，再截断为 6,000 字符摘录；因此跨过截断边界的 PEM 块不会只留下头部和密钥字节。补充资料和聊天消息在保存前先脱敏，模型的最终请求体在发送前再脱敏一次（包括按配置的 API key 字面替换）；会话历史从已脱敏的存储读取。因此 `api_key=secret` 无论来自文件、补充资料还是用户消息，都不会进入模型上下文或普通消息记录。

替换标记为 `[REDACTED]`，并记录次数。文件的完整 SHA-256 仍基于原始字节，便于核对；模型上下文只看到脱敏后的摘录。测试验证 `.env`、`secrets/` 和行内 `API_KEY=` 的值都不会出现在模型请求体、消息记录或错误信息中。

这是一层保守的文本过滤，不是完整的秘密扫描器。二进制文件、超大文件和未识别格式不会进入模型上下文；用户仍应避免把真实生产凭据放进被选项目。

## 7. 模型上下文预算

- 单次分析默认 24,000 字符预算；
- 单文件默认最多 512,000 字节进入上下文（超过则只保留指纹）；
- 摘录最多 6,000 字符；
- 二进制文件只记录指纹；
- 补充资料以 `supplement:标题` 作为来源，并记录内容指纹。

预算用尽时，剩余文件仍出现在快照中，但 `sent: false`，原因写入 `sent_scope`。界面显示“来源 N / 总数 M”，避免把“扫描到”误当成“发送给模型”。

## 8. 未验证与限制

- 容器模式尚未实现；非 `host` 模式直接失败关闭，未在容器内实跑 UID/SELinux/只读挂载差异。
- 根目录身份用 `(device, inode)` 记录；在不提供稳定 inode 的文件系统上，重扫可能仍拒绝（fail closed），需要重新导入。
- macOS 的权限位测试不能替代 Linux ACL/ACL 与 rootless 容器验证。
- 内容脱敏是模式匹配，可能漏掉自定义格式；它不替代项目侧的凭据管理。
- 快照是读取时的一致性近似：文件在扫描与发送之间变化会得到新的快照摘要，但不是原子文件系统快照。
- 大仓库（超过 400 文件或大量 8 MB 文件）会截断并记录；阶段 1 不宣称支持任意规模仓库。
